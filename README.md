# Новостной агрегатор

Небольшой production-oriented агрегатор на нативном PHP 8, MySQL 8 и Memcached. Он загружает RSS [РИА Новости](https://ria.ru/export/rss2/archive/index.xml), хранит нормализованные новости и категории, показывает их с фильтрами по категории и дню публикации.

## Быстрый запуск

Нужен только Docker Desktop.

```bash
cp .env.example .env
docker compose up --build
```

После первого успешного импорта сайт доступен на [http://localhost:8080](http://localhost:8080). Перед запуском сайта одноразовый сервис `migrate` применяет версионные миграции из `database/migrations`. Повторно уже применённые миграции не запускаются, а изменение их содержимого блокирует старт. Первый импорт запускается сервисом `importer` сразу, далее — раз в 5 минут.

```bash
docker compose logs -f importer
```

Для ручного однократного импорта (без ожидания планировщика):

```bash
docker compose exec app php bin/import-rss.php
```

Остановить окружение можно через `docker compose down`. Данные MySQL намеренно сохраняются в Docker volume; для полного чистого старта используйте `docker compose down -v`. Если первая инициализация БД прервалась с ошибкой, после обновления схемы также выполните эту команду перед повторным `up`.

## Настройка

Все переменные и их безопасные локальные значения приведены в [`.env.example`](.env.example). `.env` не попадает в git. В production следует задать отдельные пароль БД, имя пользователя и адреса сервисов через переменные окружения (они имеют приоритет над `.env`).

`CACHE_TTL` задаёт время жизни свежего ответа каталога в секундах; по умолчанию 120. Ещё до пяти таких интервалов кеш может отдать предыдущую версию, пока единственный запрос обновляет ключ. `APP_TIMEZONE` влияет на отображение **и календарный фильтр**: в MySQL даты хранятся в UTC, но день пользователя вычисляется в этой зоне.

## Что внутри

```
bin/import-rss.php       CLI-задача для cron/CronJob
database/migrations/     версионные миграции схемы
public/                  единственная web-точка входа и статические стили
src/RssImporter.php      защищённое получение, разбор и атомарное сохранение RSS
src/NewsRepository.php   запросы списка и фильтров
src/Cache.php            Memcached, версионирование ключей и anti-stampede lock
```

### Модель данных

- `sources` — источник и HTTP-валидаторы `ETag`/`Last-Modified`;
- `news` — одна запись RSS-элемента, уникальная по паре `(source_id, external_id)`;
- `categories` и `news_categories` — связь many-to-many: один RSS-элемент может иметь несколько категорий;
- `import_runs` — аудит запусков, количества увиденных элементов и ошибок.

Схема использует `utf8mb4`, внешние ключи InnoDB и не допускает дублей из повторного запуска. Самые важные индексы: `news(published_at, id)` для сортировки ленты, `news_categories(category_id, news_id)` для фильтра категории и `import_runs(source_id, started_at)` для диагностики импорта.

### Производительность и устойчивость

- Лента постраничная: 20 элементов, курсор `(published_at, id)` вместо медленного `OFFSET`; нет полного `COUNT(*)` на каждом открытии страницы.
- Запросы параметризованы; входные параметры даты, страницы и slug категории строго валидируются. В HTML вывод экранируется, внешние ссылки получают `rel="noopener noreferrer"`.
- У одного импорта есть распределённая MySQL advisory-lock, поэтому параллельные cron-процессы не дублируют работу. Каждая пачка RSS сохраняется одной транзакцией.
- Импортёр использует `ETag` и `If-Modified-Since`: при `304 Not Modified` ни XML, ни таблицы новостей не обрабатываются. HTTP-клиент ограничен HTTPS, редиректами, размером ответа и таймаутами. XML разбирается с `LIBXML_NONET`, то есть без внешних сущностей/сетевых запросов.
- Memcached кеширует результат страницы и список категорий. У ключей есть версия; после успешного импорта она увеличивается, поэтому старые результаты сразу перестают читаться, без массового `flush`. Во время обновления другие запросы получают bounded stale-значение, а не создают stampede к БД. Если Memcached недоступен, сайт корректно работает напрямую с БД.
- `content_hash` позволяет не переписывать неизменившиеся поля новости или её категории при повторном получении RSS. HTTP-запрос повторяется до трёх раз только для временных сетевых ошибок, 429 и 5xx.
- Таблица `worker_status` и healthcheck импортёра делают контейнер unhealthy, если успешного импорта не было 15 минут. Это удобная точка для Docker/Kubernetes monitoring и alerting.

### Production-заметка

В демонстрации планировщик сделан отдельным контейнером для запуска одной командой. Web-слой — Nginx + PHP-FPM; наружу на localhost опубликован только Nginx, а MySQL и Memcached остаются во внутренней Docker-сети. В production рекомендуется отключить встроенный loop импортёра и запускать `php /path/to/bin/import-rss.php` системным cron или Kubernetes CronJob раз в 5 минут. Web-контейнеры можно горизонтально масштабировать: состояние сессии не используется, а кеш и блокировки разделяются через Memcached/MySQL. Пароли обязательно задаются секретами среды, не значениями из `.env.example`.

### Исторические даты

Указанный RSS РИА не имеет параметра исторической даты: он отдаёт только скользящую ленту. Поэтому приложение честно отображает только уже сохранённые новости. Для полного backfill необходим отдельный подтверждённый архивный API/фид; такой импорт должен быть фоновым job, а не выполняться внутри HTTP-запроса. Текущий планировщик гарантирует полноту дат, собранных после запуска системы.

## Проверка

Проверить синтаксис без Docker:

```bash
find src public bin -type f -name '*.php' -print0 | xargs -0 -n1 php -l
php tests/run.php
```

```bash
docker compose exec app php bin/import-rss.php
curl -I http://localhost:8080
```
